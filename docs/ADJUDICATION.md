# 编码采信裁决书：月末合并包（UTF-8 新机 / GB18030 旧机）

## 争议

整包按一种编码识别，部分线路与备注必成乱码；逐段分别识别，同一串字节可能在不同位置得到两种解释。来源采信应以整包口径一致为先，还是允许逐段恢复并逐条标注依据？

## 裁决

**采用逐段恢复并逐条标注依据，但用三条整包不变式取代"整包一种编码"的口径一致：**

1. **分段唯一**：以行首表头（可带 BOM）为界的字节段为恢复单元，一段对应一台车载机的流水，每段只许一种编码。段内不逐行摇摆。
2. **逐条可证**：每条采纳行携带 `_bytes`（来源字节区间）、`_encoding`、`_basis`（bom / strict-utf8 / strict-gb18030 / ascii-identical / scored:双方分值）。复核页可沿字节区间回读原始字节与两种候选解码，判定依据当场可验。
3. **整包解释唯一**：同一字节串（线路、备注字段）在全包只得一种解码。一旦出现两种解释，该字节串的全部出现一并隔离为 `INTERPRETATION_CONFLICT`，不做多数表决。

"整包口径一致"的正确含义不是"整包一种编码"，而是**整包每个字节只有一种解释、且每个字节被且仅被结算一次**（M6 字节级对平）。

## 判定顺序（确定性，纯字节函数）

BOM → utf-8-sig；严格 UTF-8 唯一 → utf-8；严格 GB18030 唯一 → gb18030；两种皆可且文本相同（纯 ASCII）→ 视同已证明；两种皆可且文本不同 → 领域字符评分，分差不足保证金（2 分）即 `AMBIGUOUS_DECODING`；两种皆不可 → `UNDECODABLE`。评分只奖励线路别名与备注常用字、惩罚拉丁补充区/控制区/私用区，**宁可隔离也不猜测**。

## 封存门槛

`UNDECODABLE`、`AMBIGUOUS_DECODING`、`INTERPRETATION_CONFLICT` 三类为"无法证明解释"。**任一行未证明前，批次不得封存**：已复核提交与证据导出均返回 409。解除途径只有一条——更正来源包重新上传（新摘要、新批次），系统不替人裁决。

## 操作保证

- **同包重试不新增采信记录**：批次号 = sha256(原始字节 + 参数 + 规则版本)，runs 与 blobs 均 INSERT OR IGNORE，同事务提交，响应以 `reused` 标记复用。
- **版本切换失败仍保留完整旧版**：复核改为条件更新（version 乐观锁），失败返回 409，旧版本与全部阶段数据原样保留。
- **原始文件不能误删**：原始字节按摘要存入 blobs 表，只增不删；全系统无任何删除接口；证据导出以 input_sha256 锚定原件。
- **卡日应收唯一可封存**：M7 按（卡号， 业务日）分组聚合，跨编码来源行并入同一卡日；`ready` 仅在零未证明行时成立。

## 不覆盖

段内逐行抢救不实施：一段无法证明即整段隔离（按物理行逐条登记，便于复核定位），待更正后整包重传。
